POS System

Retail and sales
CodeIgniter 4, Bootstrap, MySQL

A point-of-sale application for processing transactions and tracking sales. I planned the system with stakeholders, designed the MySQL structure for products, transactions and sales records, built the back end in CodeIgniter 4 and the cashier interface in Bootstrap, and I maintain it in production.

How the stack works together

  1. BootstrapScreens and forms
  2. ⇄
  3. CodeIgniter 4Controllers and models
  4. ⇄
  5. MySQLStored data

CodeIgniter 4 follows an MVC structure. When a cashier completes a sale, the Bootstrap form sends it to a CodeIgniter controller, which validates the input and applies the business rules. A model then records the transaction in MySQL and updates the related records. CodeIgniter renders the result back through Bootstrap views, so the screens stay responsive on the desktops and tablets used at the counter.

Why it's relevant: the role includes developing and maintaining POS software for a Food & Hospitality partner.

Computer-Aided Dispatch

Operations and coordination
Laravel, React.js, React Native, MySQL

A system for coordinating and tracking dispatch operations. Dispatchers log incoming requests and assign them in a web app, and responders receive their assignments and update their status from a mobile app, so every request can be followed through to completion. I planned it, designed the MySQL structure, built the Laravel back end, the React.js dispatcher app and the React Native responder app, and I maintain all of it.

How the stack works together

  1. React.js web appDispatchers
  2. ⇄
  3. Laravel REST APIAssignments and status
  4. ⇄
  5. MySQLRequests and history
  6. ⇄
  7. React Native appResponders

Laravel is the single back end for both apps. A dispatcher logs a request and assigns a responder in the React.js web app, which updates without full page reloads so it keeps up when requests come in quickly. Laravel validates the assignment and saves it to MySQL, and the responder sees it in the React Native app on their phone. As the responder updates their status, those changes go through the same API, so the dispatcher sees progress in the web app and every step is kept in the request's history.

Why it's relevant: one API serving a staff web app and a field mobile app is the same pattern as the admin, reseller and customer portals in the role, and dispatch tracking is close to support-ticket management.
